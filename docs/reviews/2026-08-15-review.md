## What is genuinely strong

- The three-job credential separation in the workflows (gate / model /
  publish) is real, statically enforced, and has no `${{ }}`-into-shell
  injection path. Actor checks anchor on the numeric owner ID.
- The D9 installer transaction (prepared → installed, trap-driven reconcile)
  was fault-injected during review and restored previous targets and records
  correctly in every case, exactly as documented.
- Preview-by-default is genuinely side-effect-free in all four mutating
  scripts. Mutations are one-shot with post-write re-reads (D6/D10).
- The runtime guard, isolated HOME/XDG roots, credential-free git config
  injection, and loopback-only provider closure are coherent and mostly
  test-backed.
- The documentation describes the system that actually exists — rarer than it
  should be. Most doc findings below are overclaims of degree, not fiction.

## Confirmed findings — major

1. **Rollout lineage authorization tests a phantom field.**
   `scripts/github-rollout:86-94` authorizes an `ahead` comparison only when
   `.head_commit.sha == $head`, but GitHub's compare endpoint returns no
   `head_commit` property (verified against GitHub's official OpenAPI
   description). Every true-ancestor `--central-sha` is therefore rejected;
   only the exact live head passes. Commit `89ce639` worked around this
   symptom by accepting the exact head instead of fixing the ancestor check.
   The test fixture fabricates the phantom field, so the suite validates a
   contract the real API does not honor.

2. **`scripts/oc` has no signal/exit traps.** Ctrl-C — the normal way to
   leave a TUI session — kills the script before the epilogue at
   `scripts/oc:817-825`, leaving the run record permanently `active` (or
   `provisioning`) with no `exitCode`/`endedAt`. Some die paths also leave a
   run directory with no record at all. The sibling installers follow D9 with
   EXIT-trap reconciliation; the launcher does not.

3. **Credential deny tables are pinned structurally, not by content.**
   `validate_staged_config` and `validate_runtime_guard` (`scripts/oc:100-283`)
   require only "first read entry is `*: allow`, later entries are `deny`" —
   a config whose read table is reduced to just `{"*": "allow"}` passes
   "strict semantic validation" (reproduced with the exact extracted jq).
   Removing 20 of the guard's credential deny keys also passes. Doctor and
   install-local inherit the same gap.

4. **The test suite is not hermetic to host git configuration.** Ambient
   `GIT_CONFIG_*` variables or a user `~/.gitconfig` (insteadOf rewrites,
   `commit.gpgsign`) break `tests/local-lane.test.sh:87` and others —
   reproduced in this environment. The product scrubs git config for model
   children; the tests do not scrub their own.

5. **The cloud-lane test asserts almost nothing about credentials.**
   `tests/launcher.test.sh:458-461` pins only `opencodeKey` and
   `enabled_providers` for the `--cloud` run, while the local-lane block pins
   seven credential fields. A regression dropping the unconditional
   GH/SSH scrubbing would pass the suite. (Related minor: in `--cloud` mode
   `scripts/oc:708-761` applies no provider sanitizers at all, so every other
   provider's credentials flow to the child; `enabled_providers` narrowing is
   the only layer left.)

6. **Workflow-security job-slicing can pass vacuously.**
   `tests/workflow-security.test.sh:91-99` slices the model/publish jobs with
   awk anchored on exact job names; a renamed or reordered job yields an empty
   slice and the D3 negative assertions "pass" on nothing (reproduced,
   including the worst case: `GH_TOKEN` injected into a renamed model job with
   the suite green).

## Confirmed findings — minor

Launcher (`scripts/oc`, `scripts/doctor`, `scripts/check`):
- Build clean-tree gate is fail-open: a failing `git status` reads as clean
  (`scripts/oc:566`).
- Clean/branch/HEAD gate runs before the session lock is acquired (TOCTOU
  window against rollback/sync; `scripts/oc:566-578` vs `:622-626`).
- All five policy validators run before subcommand dispatch, so `oc doctor`
  and `oc help` are unusable exactly when a policy file is broken
  (`scripts/oc:448-478`).
- Doctor's checks are a diverging subset of the launcher's (false-healthy
  reports possible), and doctor executes the binary before verifying its
  digest (`scripts/doctor:248`).
- Local credential stripping is a fail-open denylist missing known variables
  (`ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, others; `scripts/oc:717-760`).
- `scripts/check` hardcodes its inventory; new scripts/tests silently escape
  the gate.
- `OPENCODE_FLEET_STATE_ROOT`/`MANIFEST`/`WORKSPACE_ROOT`/`CONFIG`/`GUARD`/
  `ROUTES` are honored in production while `BIN`/`RECORD`/`VERSIONS` are
  test-only; a stray state-root var silently splits the global lock
  (`scripts/oc:612-616`).

Installers / rollback:
- Archive hash verified once at startup, archive re-read three times later
  with no re-verification under the lock (`scripts/install-opencode-cli:169`).
- Run rollback verifies HEAD/branch/clone identity before the lock and never
  re-verifies under it (`scripts/rollback:333`).
- Install/CLI rollback parses the install record pre-lock only
  (`scripts/rollback:237`).
- Installers silently overwrite an interrupted `prepared` transaction;
  only ROLLBACK.md's prose warns against it (`scripts/install-local:407`).
- Installed config bytes are an independent later read of the source, not the
  validated bytes (`scripts/install-local:414-416`).
- Failure reconcile leaves staged temporaries in live user directories
  (reproduced; `scripts/install-local:421`).

Rollout / workflows:
- Write detection compares blob SHAs only while tree verification demands
  mode `100644`; mode-only drift wedges apply (`scripts/github-rollout:536`).
- Repository emptiness check trusts GitHub's asynchronous `size` field
  (`scripts/github-rollout:354`).
- Environment-secret and matching-refs reads use one unpaginated API page
  (`scripts/github-rollout:430`).
- `safe_changed_path()` segment checks are dead after the first newline in a
  path (`.github/workflows/build.yml:427`, publish copy `:549`).
- D7's README/docs/tests-only remote authority is enforced only by consumer
  policy plus a category denylist — the central gate never pins the allowlist
  to the risk-class template (`.github/workflows/build.yml:434`).

Config / docs:
- `versions.json` workflow pins are never cross-checked against the workflow
  files; `actionsCheckout` is entirely unvalidated.
- Model catalog labels contradict the route table ("(planning)", "(heavy)",
  "(work vision)"); 8 of 11 catalogued models are unreachable via any route.
- Credential read-deny list misses `.envrc`, `id_ecdsa`/`id_dsa`/`*_sk`,
  `*.p12`/`*.pfx`/`*.ppk`, `secrets.toml` despite docs claiming coverage of
  "private keys and SSH identity files".
- README's "disables destructive Git operations, recursive deletion, and
  sudo" rests on single-spelling globs (`rm -rf*` misses `rm -fr`,
  `/bin/rm -rf`; `sudo *` misses `/usr/bin/sudo`), unlike the robust
  multi-spelling push denial.

Tests:
- Gate fails as root with a misleading mid-suite error; no fail-fast.
- `post_has_retry` recognizes one exact curl formatting; zero-match passes.
- No lock-contention tests for rollback/sync-clones despite D9's four-way
  claim; run-rollback refusal paths and staged-change capture untested; zero
  interruption coverage; launcher negative tests assert only nonzero exit;
  gate positive coverage is review-on-PR only (`/oc plan` and issue-target
  paths never executed).

## Refuted during verification

- "Session lock fd 9 leaks into the opencode child, so a surviving daemon
  wedges the lane" — refuted empirically. The pinned 1.18.4 binary is
  Bun-compiled; Bun sets `O_CLOEXEC` on inherited non-stdio fds at startup
  (confirmed via `/proc/<pid>/fdinfo` against the exact sha-pinned binary).
  Only a genuinely running session holds the lock, which is the design.
  `9>&-` on the child invocation remains harmless hygiene.

## Goal-fit assessment

Judged as a hardened control plane, this repository is excellent. Judged
against the owner's stated next phase — daily, active practice with local
models — it under-serves: routes forbid 9 of the 11 staged models, practice
outside a catalogued GitHub repository is impossible by design, run records
are write-only evidence with no reading tools, worktree promotion is
undocumented, and nothing checks that Ollama itself is up before a session
launches. Proposed remedies, each with its doctrine impact, are specified in
[2026-08-15-opus-implementation-guide.md](2026-08-15-opus-implementation-guide.md).
